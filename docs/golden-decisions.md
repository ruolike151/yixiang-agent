# golden 集的两条已知 MISS：定案

**纪律：golden 集只增不改。** 改了期望值，`release_gate` 的第 4 项（检索 top-3 ≥60%）
就变成"跟自己的改动对齐"，不再是回归警报。所以下面两条**留在考卷里**，把原因写在这儿。

## 一、`名字里带夏天的动画` → 期望 `["夏日重现", "夏日大作战"]`

- **实测**：纯 FTS5 命中，离线假嵌入（`YIXIANG_EMBED_BACKEND=hash`）这一路失手。
  2026-09-20 实测 top-3 是 `你的名字。 / 头脑特工队 / 声之形`。
- **定案**：留下。它是**"降级有代价"的对照用例**——删掉它，就再也测不出
  "换回 hash 后端会掉多少分"。真实嵌入（Task 8）跑通后它的表现会变，届时**只记数字，
  不改期望**。

## 二、`宫崎骏的龙猫` → 期望 `["龙猫"]`

- **实测**：离线语料没有导演字段，纯 FTS5 下命中不了。
  2026-09-20 实测 top-3 是 `你的名字。 / 疯狂的石头 / 凉宫春日的忧郁`。
- **定案**：留下。它标记的是**"语料缺字段"**，不是调参能修的问题。修法只有两条：
  真抓取时把导演/制作公司字段带进来（Task 7 之后评估），或接受它是已知缺口。
  **不允许**通过改期望值让它变绿。

## 三、真抓取之后的语料范围规则

这 20 条是按 **31 部离线语料**（`evals/fixtures/media_sample.json`）标注的。
Task 7 真抓取 Bangumi 之后语料会变大，可能出现：

> 原来命中的 query 现在 top-3 里挤进了别的片 → 看着像退步，其实是**考卷与语料不匹配**。

**处理规则（按顺序）**：

1. 先看 `release_gate` 第 4 项的**数字**（hit_rate / MRR），别先看单条；
2. 单条掉出去时，把"query / 期望 / 现在的 top-3 / 语料规模"记进本文件的"实测记录"小节；
3. 只有当**期望值本身写错了**才动 `media.jsonl` 的 `expect`——且必须在本文件留下改动理由与日期；
4. 语料规模变化导致的分数波动，写进 `docs/NUMBERS.md`，不写进 golden。

复现命令（离线、不联网、不调模型）：

```powershell
$env:YIXIANG_EMBED_BACKEND="hash"; .venv\Scripts\python.exe -m yixiang rag eval
```
